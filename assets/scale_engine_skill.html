Vibe Coding Skill Asset v1.0.0

资产名称：多属性测量与问卷系统引擎生成器 (multi-scale-engine-generator)

一、 方法论认知对齐 (Methodology Alignment)

本资产完全遵循 tradecatlabs/vibe-coding-cn 的开发哲学。当此技能被注入 AI 协作窗口时，AI 将被赋予以下工程认知：

  • 生成域边界锁定：不再产生无法追溯逻辑和数据的硬编码前端页面，强制转为“数据驱动（Data-Driven）”架构。
  • 胶水能力编排：不重复编写轮子，将 Streamlit 1.60.0+（会话状态View）、pytest（算法质量门禁）、Supabase/PostgreSQL（云端数据安全持久化）以及 CSS 作用域隔离令牌 进行高内聚拼接。
  • 隔离审查规范：所有的算法逻辑更改必须经过隔离测试验证，拒绝让生成器执行自我偏好审查。

二、 标准输入接口定义 (Standard Input Schema)

在复用此技能时，用户（你）只需向 AI 提供以下数据接口。AI 即可完全理解业务，并在 0 行代码修改的情况下生成全新的问卷：

  1. 量表元数据： 量表名称、指导语文本、单页题目渲染密度（QUESTIONS_PER_PAGE）。
  2. 题库对象： 包含 id 与 text 的题目列表 JSON。
  3. 选项字典： 包含 label 与对应权重 score 的多级李克特选项配置。
  4. 算法约束： 得分的极端边界条件、逆向计分题号（如有）、各因子的题号映射规则。

三、 标准化物理目录树架构

无论生成任何量表，AI 必须严格遵守以下物理文件层级的解耦与隔离规范：

  • [项目根目录]/data/scales.json：数据层 (Model)。存储纯数据配置。
  • [项目根目录]/logic/scoring.py：逻辑层 (Logic / Controller)。编写纯函数计分引擎，强类型约束。
  • [项目根目录]/logic/database.py：持久化层 (Persistence)。通过 RLS 隔离策略将数据安全写入 Supabase。
  • [项目根目录]/tests/test_scoring.py：质量门禁层 (Quality Gate)。存放 pytest 自动化测试用例。
  • [项目根目录]/app.py：控制层与视图层 (View)。加载 CSS、Session State 状态保持、表单阻断式校验、动态路由。
  • [项目根目录]/assets/custom.css：表现设计层 (Style Token)。限制作用域，覆写原生单选组件，实现选项尺寸递增。

四、 终极资产：Vibe Coding 技能投喂 Prompt 模板

当你需要开发新领域的问卷或评测工具时（无论是财务能力评估、用户满意度还是新的心理量表），请直接复制以下灰色框内的全部文本，新建一个项目，直接投喂给 Windsurf 或 Claude 的对话框：

# Vibe Coding Skill: multi-scale-engine-generator 你现在是高级软件架构师，正在执行“多属性测量与问卷系统引擎生成器”的高阶技能。 请读取给定量表的数据定义，严格遵循以下 5 层软件工程架构规范在本地进行环境配置与代码生成。 ## 1. 物理目录与解耦规范 - 题库必须写入 `data/scales.json`（Model 层，禁止硬编码题目）。 - 计分逻辑必须写入 `logic/scoring.py`（Logic 层，禁止与 UI 混合）。 - 数据库操作必须写入 `logic/database.py`（采用 supabase，参数对齐）。 - 自动化测试必须写入 `tests/test_scoring.py`（Quality Gate）。 - 主程序必须写入 `app.py`（View 层，Streamlit）。 - 样式修饰必须写入 `assets/custom.css`（CSS 作用域隔离）。 ## 2. 严格质量门禁规则 (Quality Gates) - 在 `logic/scoring.py` 中，所有计算函数必须使用强类型约束（Type Hints）如 `List[int], Dict[str, Union[int, str]]`。 - 必须编写防呆边界拦截（如少答题、超纲分数必须在函数入口直接抛出 ValueError）。 - 必须使用 `pytest` 编写 4 个以上的自动化极值测试。测试全绿通过前，禁止开发前端页面。 - 严格表单校验：在 `app.py` 中，使用 `st.radio` 且设置 `index=None` 取消默认选择。未填满当前页所有题目时，必须在前端红字阻断跳转或提交。 ## 3. 表现层魔改规范 (CSS Overriding) - 禁止使用 `*` 通配符进行全局字体覆写，必须使用 scoped（作用域选择器）防止污染 Streamlit 官方头部和侧边栏的图标字体。 - 覆盖 `.stApp` 将背景色设置为书香木质渐变。 - 使用 `[data-testid="stRadio"]` 覆写单选框容器为白色等宽卡片（width: 100%; box-sizing: border-box）。 - 隐藏原生 radio 的圆点。重塑 `label` 为垂直排布（文字在上，自绘空心圆在下）。 - 根据 `scales.json` 的选项个数，使用 `label:nth-child(n)::after` 伪元素实现圆圈大小的等比级数递增，选中时使用 `#3f6653` 进行实心填充。 ## 4. 交付与配置 - 必须生成干净的 `requirements.txt`。 - 本地开发验证完成后，必须指导用户提交 Git 闭环，并配置 Streamlit Cloud Secrets。 现在，请等待我向你输入新的量表数据定义，并准备开始拆解 TODO.md 任务表。
